# 技术备忘：多语言（繁体）与首屏白屏

本文档记录本站两个已处理问题的**叫法**、**现象**、**原因**与**解决方案**，便于后续维护与排查。

---

## 一、多语言问题（首页繁体不完整）

### 需求 / 问题叫什么

| 叫法 | 说明 |
|------|------|
| **简繁数据源不统一** | 子页走 `pageData`，首页另有一套 JSX 硬编码文案 |
| **客户端导航与刷新不一致** | 点首页/Logo 进 `/zh-hant/` 时正文部分仍是简体；右键刷新后变全繁体 |
| **DOM 补丁转繁失败** | 依赖 `useEffect` 扫描 `document.body` 做 OpenCC，与页面切换动画时序冲突 |

业界相关概念（便于检索）：**i18n 数据源单一化**、**避免 CSR-only 语言补丁**、**SSG 与 CSR 文案一致**。

### 现象

- 子页（如 `/zh-hant/ouyi-okx-web/`）繁体正常。
- 首页 `/zh-hant/`：导航等用 `t()` 的已是繁体，**正文大段仍为简体**。
- **点击**进首页：繁体不全；**整页刷新**：往往变全繁体。

### 原因（根因）

1. **子页机制（正确）**  
   `constants.ts` → 构建期 `PAGES_ZH_HANT`（OpenCC）→ `getPagesByLocale(locale)` → 渲染 `pageData.content` / `faqs` 等。

2. **首页机制（曾错误）**  
   - 使用 `BeginnerIndexContent`，文案**写死在组件 JSX** 里，未读 `PAGES_ZH_HANT`。  
   - Hero 曾硬编码简体，或误用 SEO 用 `pageData.title`（带下划线关键词）。  
   - 另有一段 **`useEffect` + TreeWalker** 在路由变化时扫 DOM 转繁体：对 SEO 几乎无效，且在 `AnimatePresence mode="wait"` 下**早于新正文插入**执行，导致补丁失效。

3. **`home.content` 与首页 UI 重复**  
   `constants` 里已有 `home.content` / `home.faqs`，但首页未接入，形成两套维护。

### 解决方案（已实施，方案二思路）

**原则**：与子页同一套——**构建期繁体数据 + 渲染期直接输出**，不靠 JS 事后改 DOM。

| 项 | 做法 |
|----|------|
| 数据 | 在 `home` 增加 `homeSections`（结构化区块文案），随 `PAGES` 经 `convertDeep` 进入 `PAGES_ZH_HANT` |
| 组件 | `BeginnerIndexContent` 只读 `pageData.homeSections`、`pageData.faqs` |
| Hero 展示 | `homeSections.heroTitle` 可读标题；`pageData.title` 仍用于 `<title>` / meta SEO |
| 移除 | 删除 `document.body` TreeWalker 繁体补丁 `useEffect` |
| 工具 | `src/locales/convert.ts` 抽出 `convertDeep`，`zh-Hant.ts` 复用 |

**相关文件**

- `src/constants.ts` — `HomeSections`、`home.homeSections`
- `src/locales/zh-Hant.ts`、`src/locales/convert.ts`
- `src/i18n.ts` — `getPagesByLocale`
- `src/App.tsx` — `BeginnerIndexContent`、`heroDisplayTitle`

**代表提交**（以 git 历史为准）

- `7fa9b5e` — 首页繁体接回 pageData、移除 DOM 补丁  
- 后续 — `heroTitle` 与 SEO `title` 分离  

### 验证方式

- `npm run build` 后查看 `out/zh-hant/index.html` 源码，正文应为繁体且无依赖 JS。  
- 浏览器：在 `/zh-hant/` 子页**点击**回首页，正文应与刷新一致为繁体。

## 二、首屏白屏问题

### 需求 / 问题叫什么

| 叫法 | 说明 |
|------|------|
| **SSG 首屏不可见内容** | 静态 HTML 中主区域为 `opacity: 0`，需等 JS 才显示 |
| **FOUC 类问题（变体）** | 非样式表闪烁，而是 **Motion 入场动画** 导致的首屏空白 |
| **LCP 受损** | 最大内容绘制推迟到 JS 执行后，影响 Core Web Vitals |

### 现象

- 顶栏导航立即显示，**主内容区长时间白屏**，随后淡入出现。  
- 首页、所有内页、繁体路径**均有**（共用同一 `App` 布局）。  
- 静态「查看网页源代码」中可见正文 HTML，但带 `style="opacity:0;..."`。

### 原因

`App.tsx` 主内容外包：

```tsx
<motion.div
  key={pathname}
  initial={{ opacity: 0, y: 15 }}
  animate={{ opacity: 1, y: 0 }}
  ...
/>
```

Next 静态导出时把 **initial** 写入 HTML。在多个 `defer` 脚本加载并完成 hydration 之前，主内容不可见。

### 解决方案（已实施）

**策略**：**首屏不做 opacity 入场**；**站内路由切换**仍保留淡入。

```tsx
const skipPageEnterAnimation = useRef(true);

useEffect(() => {
  skipPageEnterAnimation.current = false;
}, []);

const pageEnterInitial = skipPageEnterAnimation.current
  ? false
  : { opacity: 0, y: 15 };

<motion.div initial={pageEnterInitial} animate={{ opacity: 1, y: 0 }} ... />
```

| 场景 | 行为 |
|------|------|
| 首次打开任意 URL（含 `/zh-hant/*`） | `initial={false}`，HTML 无 `opacity:0`，首屏立即可见 |
| 站内 `router.push` 换页 | `initial` 为淡入，保留过渡 |

**范围**：全站所有 `[[...slug]]` 页面一次修复（同一 `motion.div`）。

**相关文件**

- `src/App.tsx` — `skipPageEnterAnimation`、`pageEnterInitial`

**代表提交**

- `f45951a` — fix: 首屏取消主内容 opacity 入场，避免 SSG 白屏并改善 LCP

### 验证方式

- `out/index.html`、`out/ouyi-okx-web/index.html` 中不应出现主内容容器的 `opacity:0`。  
- 线上强刷后，首屏应直接看到 Hero/正文，而非仅导航栏。

## 五、方案名称说明：是不是叫「数据层 i18n / 去 DOM 补丁」？跟 i18n 比利弊？

> 以下内容为答疑原文记录，便于理解命名与和「常见 i18n」的差异。

**不完全是。**「数据层 i18n / 去 DOM 补丁」是我用来概括你们**实际做法**的简称，不是某个官方库或标准术语名。

更准确可以拆成两句：

1. **主方案**：构建期繁体数据 + 按 URL 选 `pageData` 直出（与子页同机制）  
2. **同时做的**：去掉用 JS 扫整页 DOM 转繁的补丁  

导航等少量壳层仍用 `t()` / `localizeText`，所以也不是「完全没有 i18n」，而是 **正文以数据层为主，运行时再转一层为辅**。

---

### 和你们这套 vs「常见 i18n」对比

这里「常见 i18n」指：`react-i18next`、JSON 语言包、`t('key')` 包一层、或运行时 OpenCC 扫 DOM 等。

| 维度 | 你们现在（数据层为主） | 常见运行时 i18n（`t(key)` + 语言包） |
|------|------------------------|--------------------------------------|
| **SEO / 静态 HTML** | 好：`npm run build` 后 `/zh-hant/` 的 HTML 里已是繁体 | 取决于实现；纯 CSR 或首屏隐藏会差 |
| **与子页一致性** | 好：首页、内页都走 `PAGES_ZH_HANT` | 看是否所有文案都进语言包 |
| **首屏 / 白屏** | 不依赖 DOM 补丁，不拖首屏 | DOM 补丁差；大量 `t()` 一般还好 |
| **维护** | 改 `constants` 一处，构建自动转繁 | 改 JSON/键值，或简繁各维护一套 |
| **路由** | 用路径 `/` 与 `/zh-hant/`（利于 hreflang） | 也常支持，但要自己配 |
| **包体积** | 无额外 i18n 库；OpenCC 只在构建时用 | 多一个 i18n 运行时（通常不大） |
| **灵活性** | 低：新语言要加一套数据 + 路径规则 | 高：加 locale、加 JSON 即可 |
| **动态文案** | 弱：不适合频繁变的 UI 文案 | 强：组件里 `t()` 很方便 |
| **翻译质量** | OpenCC 机翻，术语需人工改 constants | 可人工翻译 JSON，质量可控 |
| **客户端切换语言** | 要跳 URL（`router.push`），符合静态站 | 可 cookie/下拉不切 URL（静态站不推荐） |

---

### 「去 DOM 补丁」单独说

| | DOM 补丁（已废弃） | 数据层（现在） |
|--|-------------------|----------------|
| 做法 | JS 加载后扫 `document.body` 改文字 | HTML 里本来就是对的字 |
| SEO | 爬虫看 HTML 尚可，但不稳 | 稳定 |
| 点击换页 | 和动画抢时序，首页曾不全繁体 | 与子页一致 |
| 维护 | 两套来源（数据 + 页面上偶然的字） | 以 `constants` / `homeSections` 为准 |

所以：**不是「叫 i18n」这么简单**，而是 **静态站 + 简繁分路径 + 构建期转繁**；和通用 i18n 库 solving 的问题有重叠，但实现路径不同。

---

### 利弊一句话

**利**：最适合你们这种 **GitHub Pages 静态导出 + 要强 SEO + 简繁两套 URL** 的站；首页、内页行为统一。  

**弊**：不适合马上加英文、日文第三语言；机翻繁体要人工校对；壳层零散文案仍得记得走 `t()` 或并进数据。

若以后要加第三种语言，更可能演进成：**路径 locale + 各语言一份 `PAGES_XX`（或 JSON）**，而不是上完整 `react-i18next`；那是后话。

---

### 直接回答（备忘用）

- **叫什么？** 正式描述用：**「构建期繁体数据 + pageData 直出」**；「数据层 i18n / 去 DOM 补丁」只是口头简称。  
- **跟 i18n 比？** 你们不是替代所有 i18n，而是 **用静态数据层解决简繁 SEO**，比运行时 i18n + DOM 补丁更适合当前项目；通用 i18n 更灵活，但对静态 SEO 站要额外保证「构建结果里字已经对」。
